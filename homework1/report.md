# 題目一：Ackermann Function

## 解題說明

本題要求以遞迴方式計算 Ackermann Function（阿克曼函數）。此函數有兩個非負整數參數 `m`、`n`，定義如下：

$$
A(m,n)=
\begin{cases}
n+1 & m=0\\
A(m-1,1) & m>0,\ n=0\\
A(m-1,A(m,n-1)) & m>0,\ n>0
\end{cases}
$$

程式中以函式 `A()` 實作上述定義，主程式則不斷讀取成對的 `m`、`n`，每讀一組就輸出一行結果，直到輸入結束為止。

## 解題策略

1. 先把數學定義中的三種情況逐一對應成程式中的三個分支，讓程式結構與定義一致。
2. 以 `m == 0` 作為遞迴的終止條件，此時不需要再呼叫自己，直接回傳 `n + 1`。
3. 當 `m > 0` 且 `n == 0` 時，問題降階成 `A(m-1, 1)`，`m` 變小，逐步逼近終止條件。
4. 當 `m > 0` 且 `n > 0` 時，先遞迴算出內層的 `A(m, n-1)`，再把該結果當作 `n` 代入外層的 `A(m-1, ?)`。
5. 每次遞迴不是 `m` 減少，就是 `m` 不變而 `n` 減少，因此兩個參數的順序關係會一直縮小，保證最後一定停在 `m == 0`。
6. 主程式利用 `while (cin >> m >> n)` 一次處理多組測資，不需要事先知道有幾組。

## 程式實作

以下為主要程式碼：

```cpp
#include<iostream>
using namespace std;

int A(int m, int n)
{
	if (m == 0)
	{
		return n + 1;
	}
	else if (m > 0 && n == 0)
	{
		return A(m - 1, 1);
	}
	else if (m > 0 && n > 0)
	{
		return A(m - 1, A(m, n - 1));
	}
}

int main()
{
	int m, n;
	while (cin >> m >> n)
	{
		cout << A(m, n) << endl;
	}
	return 0;
}
```

## 效能分析

1. 時間複雜度：Ackermann 函數的成長速度遠超過指數函數，呼叫次數會隨 `m` 增加而爆炸性成長，無法用 `O(n)`、`O(n²)` 或 `O(2ⁿ)` 這類常見形式表示。以 `m` 固定時的結果為例，`A(1,n)=n+2`、`A(2,n)=2n+3`、`A(3,n)=2^(n+3)-3`，到了 `m=4` 就已經大到實際上無法計算。
2. 空間複雜度：空間主要花在遞迴呼叫堆疊（Call Stack），最深的堆疊層數即為空間使用量，可寫成 $O(\text{recursion depth})$。
3. 輸入稍大就可能造成堆疊溢位（Stack Overflow），或讓結果超出 `int` 能表示的範圍。
4. 若輸入負數，三個條件皆不成立，函式會沒有回傳值，因此本程式預設輸入皆為非負整數。

## 結論

1. 程式以遞迴直接實作 Ackermann 函數的三條定義，所有測試結果皆與預期相符。
2. `m == 0` 是整個遞迴的出口，其餘兩種情況都會讓參數往這個出口靠近。
3. 測試資料包含 `m` 為 0、1、2、3 的情形，並同時涵蓋 `n = 0` 與 `n > 0`，三個分支皆有走到。
4. 函數成長極快，因此只適合用較小的數值測試，過大的輸入會受限於堆疊深度與 `int` 範圍。

## 申論及開發報告

### 為什麼這題一定要用遞迴

Ackermann 函數最特別的地方，在於它的第三條規則把「自己的結果」當成「自己的參數」，也就是巢狀遞迴：`A(m-1, A(m, n-1))`。這種結構很難單純改寫成一個迴圈，因為內層的值必須先算出來，外層才能繼續，而外層算完後又可能再展開出新的內層。因此本題直接使用遞迴，是最自然也最不容易出錯的做法。

### 實際展開一次：`A(1,2)`

為了確認自己真的理解遞迴的過程，我手動展開了 `A(1,2)`：

```text
A(1,2) = A(0, A(1,1))
       = A(0, A(0, A(1,0)))
       = A(0, A(0, A(0,1)))
       = A(0, A(0, 2))
       = A(0, 3)
       = 4
```

可以看到函式會先往下「展開」到 `m == 0`，再一路把結果往回「代入」，最後得到 4，與 `A(1,n)=n+2` 的規律一致。這也讓我體會到，遞迴的重點是先想清楚「什麼時候停」，再想「怎麼把問題變小」。

### 開發過程中遇到的狀況

1. **編譯警告**：函式最後一個分支使用 `else if` 而非 `else`，編譯器無法確定所有路徑都有回傳值，可能出現「control reaches end of non-void function」的警告。在輸入皆為非負整數的前提下這條路徑不會被走到，因此不影響結果，但若要更嚴謹，可把最後一個分支改成 `else`。
2. **測資的選擇**：一開始想直接測試 `A(4,1)`，結果程式因為遞迴層數過深而當掉，所以才改用 `m ≤ 3` 的測資。這個經驗讓我實際看見遞迴深度的限制。
3. **數值範圍**：`A(3,n)` 的值為 `2^(n+3)-3`，若 `n` 很大，結果會超過 `int` 的上限，若要處理更大的數需改用 `long long`，但堆疊深度的問題依然存在。

### 遞迴的優缺點

優點是程式碼幾乎就是數學定義的翻譯，邏輯清楚，也容易檢查正確性。缺點是效率極差：相同的子問題（例如 `A(1,1)`）會被重複計算許多次，而且呼叫深度會快速增加。若要提升效率，可以考慮記憶化（Memoization）或改用自行維護堆疊的非遞迴寫法，但這會讓程式變得比較複雜，不如原本的遞迴版本直觀。

# 題目二：字串排列組合

## 解題說明

本題要求輸入一個字串，輸出該字串所有字元的全排列（Permutation）。輸出時，字元與字元之間以空格隔開。

例如輸入：

```text
ABC
```

輸出：

```text
A B C
A C B
B A C
B C A
C B A
C A B
```

## 解題策略

1. 把「排出整個字串」切成「一個位置一個位置決定」：先決定第 0 個位置放哪個字元，再決定第 1 個位置，依此類推。
2. 以參數 `k` 代表目前正在決定的位置，`m` 代表最後一個位置的索引。
3. 當 `k == m` 時，代表前面所有位置都已經決定好，這就是一種完整的排列，直接輸出。
4. 否則，用迴圈讓位置 `k` 依序嘗試 `a[k]` 到 `a[m]` 中的每一個字元：把候選字元 `swap` 到位置 `k`。
5. 交換之後，位置 `k` 的字元就固定了，接著遞迴處理位置 `k+1`。
6. 遞迴回來後，再 `swap` 一次還原字串，確保下一個候選字元是從「原本的狀態」開始交換，不會造成排列遺漏或重複。

## 程式實作

以下為主要程式碼：

```cpp
#include<iostream>
#include<string>
#include<algorithm>
using namespace std;

void Permutations(string &a, const int k, const int m)
{
	if (k == m)
	{
		for (int i = 0; i <= m; i++)
			cout << a[i] << " ";
		cout << endl;
	}
	else
		for (int i = k; i <= m; i++)
		{
			swap(a[k], a[i]);
			Permutations(a, k + 1, m);
			swap(a[k], a[i]);
		}
}

int main()
{
	string n;
	cin >> n;
	int length = n.length();
	Permutations(n, 0, length - 1);
}
```

## 程式說明

函式原型如下：

```cpp
void Permutations(string &a, const int k, const int m)
```

- `a`：以參考方式傳入的字串，所有交換都直接發生在同一個字串上，不會複製。
- `k`：目前要決定的位置。
- `m`：字串最後一個位置的索引。

終止條件 `k == m` 成立時，以迴圈輸出 `a[0]` 到 `a[m]`，每個字元後面接一個空格，最後換行。

其餘情況則進入下列迴圈：

```cpp
for (int i = k; i <= m; i++)
{
	swap(a[k], a[i]);
	Permutations(a, k + 1, m);
	swap(a[k], a[i]);
}
```

第一個 `swap` 負責「選擇」，遞迴呼叫負責「往下一層走」，第二個 `swap` 負責「還原」。這三個動作缺一不可，尤其少了還原，後面的排列就會建立在被打亂的字串上，結果會出錯。

## 效能分析

設輸入字串長度為 $n$。

1. 時間複雜度：長度為 $n$ 的字串共有 $n!$ 種排列，而每一種排列輸出時需要走訪 $n$ 個字元，因此整體時間約為：

$$
O(n \times n!)
$$

2. 空間複雜度：遞迴最深會有 $n$ 層，所以呼叫堆疊的使用量為 $O(n)$。
3. 由於所有交換都在原字串上完成，沒有額外配置新的字串，因此除了輸入本身之外，額外空間同樣為 $O(n)$。
4. 本程式並未檢查重複字元，若輸入含有相同字元，會輸出內容相同的重複排列，總行數仍為 $n!$。

## 結論

1. 程式能以遞迴加上 `swap` 產生字串的所有排列，且各測試的排列數皆等於 $n!$。
2. 「交換、遞迴、還原」的三步驟是程式正確運作的關鍵，其中還原動作確保每一層遞迴結束後字串回到原狀。
3. 時間複雜度為 $O(n \times n!)$，空間複雜度為 $O(n)$。
4. 排列數量成階乘成長，字串長度一旦超過 10 左右，輸出量就會大到難以處理。
5. 程式不會處理重複字元，輸入相同字元時會得到內容相同的重複排列。

## 申論及開發報告

### 想法的來源：把大問題切成同型的小問題

剛開始看到這題時，我的第一個念頭是用 `n` 層迴圈，但字串長度不固定，迴圈層數就無法事先寫死。後來換個角度思考：若第一個位置已經決定了，剩下的部分其實就是「長度少一」的同一個排列問題。這正是遞迴擅長處理的情況，所以每多決定一個位置，就往下遞迴一層，直到所有位置都決定完畢。

### 用 `ABC` 追蹤執行過程

以輸入 `ABC` 為例，呼叫 `Permutations("ABC", 0, 2)` 的過程大致如下：

```text
k=0, i=0: swap(a[0],a[0]) -> ABC
    k=1, i=1: swap(a[1],a[1]) -> ABC -> k=2 輸出 A B C
    k=1, i=2: swap(a[1],a[2]) -> ACB -> k=2 輸出 A C B，還原為 ABC
k=0, i=1: swap(a[0],a[1]) -> BAC
    k=1, i=1: BAC -> 輸出 B A C
    k=1, i=2: BCA -> 輸出 B C A，還原為 BAC
k=0, i=2: swap(a[0],a[2]) -> CAB（由還原後的 ABC 交換而來）
    ...
```

從追蹤可以看出，位置 0 會依序被換成 `A`、`B`、`C`，而每次換完，後面剩下的兩個字元再各自排列一次，所以總數是 $3 \times 2 \times 1 = 6$。

### 為什麼最後一定要再 `swap` 一次

我特地試過把第二個 `swap` 拿掉，結果發現輸出的排列出現重複，同時也漏掉了部分排列。原因是第一層迴圈換到 `i=1` 時，字串已經被前一輪的遞迴改過，不再是原本的 `ABC`，後續交換的對象就錯了。這個實驗讓我明白，這種直接修改同一份資料的遞迴寫法，必須在返回前把狀態還原，這個概念就是回溯（Backtracking）。

### 與其他寫法的比較

另一種常見的做法是額外準備一個 `used[]` 陣列與一個暫存字串，每層遞迴挑選尚未使用的字元，附加到暫存字串後面。這種寫法的優點是排列的輸出順序剛好符合字典序（若原字串已排序），但需要額外的陣列與字串空間。本程式使用 `swap` 直接在原字串上操作，空間較省、程式碼也較短，缺點是輸出順序不是字典序，例如 `ABC` 的最後兩筆會是 `C B A`、`C A B`。

### 遞迴的優缺點

優點是邏輯簡潔，只要定義好「終止條件」與「縮小問題的方式」，就能涵蓋任意長度的字串，程式碼不到二十行。缺點是排列數成階乘成長，例如：

```text
5! = 120
6! = 720
8! = 40320
10! = 3628800
```

當字串長度增加時，執行時間與輸出量都會急劇增加，因此這個方法只適用於長度不大的字串。另外，遇到重複字元時若想避免重複排列，必須額外加入判斷（例如以集合記錄本層已使用過的字元），這是本程式可以再改進的地方。

# 作業總結

本次作業以遞迴實作了兩個問題，兩者雖然都用到遞迴，但思考方式不同。

## 題目一：Ackermann Function

這題的重點是「照著定義寫」：定義本身就是遞迴，而且含有巢狀的自我呼叫，透過它可以學到終止條件的設計，以及遞迴深度與數值範圍對程式的限制。

```text
m == 0
    ↓
n + 1

m > 0 且 n == 0
    ↓
A(m-1, 1)

m > 0 且 n > 0
    ↓
A(m-1, A(m, n-1))
```

## 題目二：Permutation

這題的重點是「逐位置決定，並在返回前還原」：利用 `swap` 與遞迴窮舉所有可能，並透過回溯讓同一份字串可以重複使用。

```text
決定位置 k
    ↓
swap 選擇字元
    ↓
遞迴決定位置 k+1
    ↓
swap 還原字串
    ↓
換下一個候選字元
```

# 兩題複雜度比較

| 題目 | 主要演算法 | 時間複雜度 | 空間複雜度 |
|------|------------|------------|------------|
| 題目一 Ackermann | 遞迴 | 呼叫次數隨 Ackermann 函數急遽成長 | $O(\text{recursion depth})$ |
| 題目二 Permutation | 遞迴 + 回溯 | $O(n \times n!)$ | $O(n)$ |

兩題的共同點是以遞迴為核心，差別在於：

- Ackermann：遞迴用來忠實呈現一個本身就遞迴的數學定義，重點在遞迴本身的行為。
- Permutation：遞迴用來窮舉所有可能的選擇，重點在狀態的保存與還原。

透過這兩題，我對遞迴的終止條件、問題縮小的方式，以及遞迴可能帶來的效能代價，都有了更具體的認識。
