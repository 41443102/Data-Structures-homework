# 題目一：Ackermann Function

## 解題說明

這題要我們算 Ackermann Function。有兩個參數 `m` 和 `n`，規則如下：

$$
A(m,n)=
\begin{cases}
n+1 & m=0\\
A(m-1,1) & m>0,\ n=0\\
A(m-1,A(m,n-1)) & m>0,\ n>0
\end{cases}
$$

這題有兩種方式：

1. **遞迴寫法**：照著定義寫，看起來直觀。
2. **非遞迴寫法**：先找出 `m` 比較小的時候的規律，再用公式或迴圈算出答案，不用一直呼叫自己。

## 方法一：遞迴寫法

### 解題策略

1. 先看定義有三種情況，直接寫成三個 `if`，跟公式對照。
2. `m == 0` 的時候直接回傳 `n + 1`。
3. `m > 0` 而且 `n == 0` 的時候，改算 `A(m-1, 1)`，`m` 。
4. `m > 0` 而且 `n > 0` 的時候要先算裡面的 `A(m, n-1)`，之後再丟進外面的 `A(m-1, ?)`。
5. 每呼叫一次，不是 `m` 變小，就是 `m` 不變但 `n` 變小，所以最後一定會走到 `m == 0`，不會無限跑下去。
6. 主程式用 `while (cin >> m >> n)`，這樣一次可以輸入很多組。

### 程式實作

```cpp
#include<iostream>
using namespace std;

int A(int m, int n)
{
    if (m == 0)
    {
        return n + 1;
    }
    else if (m > 0 && n == 0)
    {
        return A(m - 1, 1);
    }
    else if (m > 0 && n > 0)
    {
        return A(m - 1, A(m, n - 1));
    }
}

int main()
{
    int m, n;
    while (cin >> m >> n)
    {
        cout << A(m, n) << endl;
    }
    return 0;
}
```

### 效能分析

1. **時間複雜度**：呼叫的次數會隨著 `m` 變大而暴增，沒辦法用 `O(n)`、`O(n²)`、`O(2ⁿ)` 這種常見的寫法表示，只能說它成長得非常快。
2. **空間複雜度**：主要是遞迴呼叫佔用的 Call Stack，疊得越深用越多，可以寫成 $O(\text{recursion depth})$。
3. 輸入一大，不是 Stack 爆掉（Stack Overflow），就是答案超過 `int` 能放的範圍。
4. 如果輸入負數，三個 `if` 都不會成立，函式就沒有回傳值，所以這份程式預設輸入都是非負整數。

## 方法二：非遞迴寫法

### 解題策略

遞迴寫法很直觀，但需要一直呼叫自己。所以先把 `m` 從 0 開始算，看有沒有規律：

- `m = 0`：`A(0,n) = n + 1`，這個是公式。
- `m = 1`：`A(1,n) = A(0, A(1,n-1)) = A(1,n-1) + 1`，而且 `A(1,0) = A(0,1) = 2`，所以每多一個 `n` 就加 1，結果是 **`n + 2`**。
- `m = 2`：`A(2,n) = A(1, A(2,n-1)) = A(2,n-1) + 2`，而且 `A(2,0) = A(1,1) = 3`，所以每多一個 `n` 就加 2，結果是 **`2n + 3`**。
- `m = 3`：`A(3,n) = A(2, A(3,n-1)) = 2 × A(3,n-1) + 3`，而且 `A(3,0) = A(2,1) = 5`。如果兩邊都加 3，就變成 `A(3,n) + 3 = 2 × (A(3,n-1) + 3)`，也就是每多一個 `n` 就乘 2，起點是 `A(3,0) + 3 = 8 = 2³`，所以結果是 **`2^(n+3) - 3`**。

整理成表：

| `m` | 公式 |
|-----|------|
| 0 | `n + 1` |
| 1 | `n + 2` |
| 2 | `2n + 3` |
| 3 | `2^(n+3) - 3` |

程式的做法就是：

1. 用 `if / else if` 判斷 `m` 是 0、1、2、3 的哪一種，直接套公式。
2. `m == 3` 的時候要算 2 的 `n+3` 次方，我用一個 `for` 迴圈，從 `r = 1` 開始乘 `n + 3` 次 2，最後減 3。
3. 如果 `m` 不是 0 到 3，這支程式沒有支援，就回傳 `-1` 表示算不了。

### 程式實作

```cpp
#include <iostream>
using namespace std;

int A(int m, int n)
{
    if (m == 0)
    {
        return n + 1;
    }
    else if (m == 1)
    {
        return n + 2;
    }
    else if (m == 2)
    {
        return 2 * n + 3;
    }
    else if (m == 3)
    {
        int r = 1;

        for (int i = 0; i < n + 3; i++)
        {
            r = r * 2;
        }

        return r - 3;
    }

    return -1;
}

int main()
{
    int m, n;

    cin >> m >> n;

    cout << A(m, n) << endl; //呼叫函式 A(m, n) 計算值

    return 0;
}
```

### 效能分析

1. **時間複雜度**：
   - `m = 0、1、2` 的時候只做一次加法或乘法，是 $O(1)$。
   - `m = 3` 的時候迴圈要跑 `n + 3` 次，所以是 $O(n)$。
2. **空間複雜度**：沒有遞迴，只用到 `r`、`i` 幾個變數，是 $O(1)$。
3. **限制**：
   - 只支援 `m ≤ 3`，`m ≥ 4` 會回傳 `-1`。
   - `m = 3` 的時候，`n` 太大會讓 `r` 超過 `int` 的範圍（大約 `n + 3 ≥ 31` 就會溢位），答案會不正確。
   - 主程式只讀一組輸入，跟遞迴版用 `while` 讀很多組不一樣。

## 兩種寫法比較

| 比較項目 | 遞迴寫法 | 非遞迴寫法 |
|----------|----------|------------|
| 做法 | 照著定義一層一層呼叫 | 先找規律，再直接套公式 |
| 支援的 `m` | 理論上都可以（但實際上會算不完） | 只有 `0 ~ 3` |
| 時間 | 呼叫次數暴增 | `O(1)` 或 `O(n)` |
| 空間 | `O(recursion depth)` | `O(1)` |
| 會不會 Stack Overflow | 會 | 不會 |
| 好不好懂 | 跟定義一模一樣，很好懂 | 要先推公式，比較不直觀 |

簡單講，遞迴寫法比較「正統」，非遞迴寫法比較「快」，但是它是靠我們先把規律算出來才快的，不是真的把 Ackermann 函數通用地改成迴圈。

## 結論

1. 遞迴寫法完全照著定義，三個分支都有被測到，結果都對。
2. 非遞迴寫法利用 `m = 0 ~ 3` 的規律，直接用公式和一個迴圈算出答案，速度快很多，也不會有 Stack Overflow 的問題。
3. 但非遞迴寫法只能算 `m ≤ 3`，而且 `n` 太大還是會碰到 `int` 溢位。
4. Ackermann 函數成長非常快，所以測試的時候只能挑比較小的數字。
5. 兩種寫法算出來的結果一致，可以互相拿來驗證對方。

## 申論及開發報告

### 為什麼一開始會選遞迴

Ackermann 函數的第三條規則是 `A(m-1, A(m, n-1))`，也就是把「自己的結果」又拿來當「自己的參數」。這種巢狀的結構很難直接寫成一個迴圈，因為你要先把裡面的算完，外面才有辦法繼續。所以我一開始就用遞迴，因為它最貼近定義，寫起來也最不容易出錯。

### 手動展開 `A(1,2)`

為了搞懂遞迴，所以算了 `A(1,2)`：

```text
A(1,2) = A(0, A(1,1))
       = A(0, A(0, A(1,0)))
       = A(0, A(0, A(0,1)))
       = A(0, A(0, 2))
       = A(0, 3)
       = 4
```

它先往下拆到 `m == 0`，再把答案往回帶。結果是 4，剛好跟 `n + 2` 對得上，也是我後來想到要找規律的原因：既然 `A(1,n)` 永遠是 `n + 2`，那何必每次都真的拆開來算。

### 為什麼想到要寫非遞迴

遞迴版有個問題：`m` 一大，呼叫的層數就會深到不行，甚至 Stack 直接爆掉。我把 `m = 1、2、3` 的結果手算出來之後，發現它們其實都有很單純的公式，那就可以直接用公式算，不用真的去遞迴。

這也讓我學到一件事：有時候遞迴只是「把問題寫出來」的工具，如果能先把問題分析透，就有機會用更省的方式解決。

### 寫程式時需要注意的地方

1. **遞迴版的編譯警告**：最後一個分支是 `else if`，編譯器沒辦法確定每條路徑都有 `return`，可能會跳出 "control reaches end of non-void function" 的警告。在輸入都是非負整數的情況下不會走到那裡，所以不影響結果，不過如果想要更嚴謹，可以把最後一個改成 `else`。
2. **測資的挑選**：`m` 太大的話，遞迴會深到可能讓程式當掉，所以測資我只用 `m ≤ 3`。
3. **非遞迴版的 `-1`**：這個回傳值只是用來代表「這個 `m` 我沒支援」，它跟 Ackermann 函數本身的值沒有關係，因為正常的結果都是正數。
4. **數值範圍**：`A(3,n) = 2^(n+3) - 3` 長得很快，`n` 稍微大一點就會超過 `int`，要算更大的數可以改用 `long long`。

### 兩種寫法各自的優缺點

遞迴的優點是程式跟數學定義長得一樣，好懂，也很好檢查；缺點是效率差，而且會重複算很多一樣的東西（例如 `A(1,1)`）。

非遞迴版的優點是快，缺點是只能處理特定幾個 `m`，而且需要先推公式，如果 `m` 變成 4 以上就沒辦法了。

# 題目二：冪集（Power Set）

## 解題說明

這題是輸入一個字串，把每個字元當成集合裡的一個元素，然後把所有的子集合都印出來，也包含空集合，有 $n$ 個元素的集合會有 $2^n$ 個子集合。

例如輸入：

```text
ABC
```

會印出 8 行（第一行是空集合，所以是空白行）：

```text
(空字串)
C
B
BC
A
AC
AB
ABC
```

## 解題策略

1. 對每一個字元來說，只有兩種選擇：**放進子集合**，或是**不放**。
2. 用 `index` 記錄現在在看第幾個字元，用 `current` 記錄到目前為止已經選了哪些字元。
3. 當 `index` 等於字串長度，代表每個字元都決定完了，這時候的 `current` 就是一個完整的子集合，直接印出來就可以了。
4. 還沒決定完的話，就分兩條路繼續往下走：
   - 不選這個字元：`powerset(a, index + 1, current)`。
   - 選這個字元：`powerset(a, index + 1, current + a[index])`。
5. 每個字元都分兩條路，所以最後會有 $2^n$ 個結果，剛好就是所有的子集合。
6. 因為每次都是產生一個新的字串傳下去，沒有去改原本的字串，所以不用像排列那題一樣，遞迴完還要把東西還原。

## 程式實作

```cpp
#include<iostream>
#include<string>
#include<algorithm>
using namespace std;

void powerset(string a, int index, string current)
{
	if (index == a.length())
	{
		cout << current << endl;
		return;
	}
	powerset(a, index + 1, current);
	powerset(a, index + 1, current + a[index]);
}

int main()
{
	string n;
	cin >> n;
	powerset(n, 0, "");
}
```

## 程式說明

函式的參數：

```cpp
void powerset(string a, int index, string current)
```

- `a`：原本輸入的字串，可以選的字元都在裡面。
- `index`：現在要決定的是第幾個字元。
- `current`：目前這條路已經選的字元。

當所有字元都決定完：

```cpp
if (index == a.length())
{
	cout << current << endl;
	return;
}
```

就把 `current` 印出來，然後 `return` 回上一層。

還沒結束的話，就呼叫兩次：

```cpp
powerset(a, index + 1, current);
powerset(a, index + 1, current + a[index]);
```

第一行是不選，`current` 不變；第二行是選，把字元接到 `current` 後面。因為不選寫在前面，所以空集合會最先印出來。

## 效能分析

假設字串長度是 $n$。

1. **時間複雜度**：每多一個字元，分支就變兩倍，所以總共有 $2^n$ 個結果，函式大約被呼叫 $2^{n+1}-1$ 次。每次呼叫還要複製字串，印出來也要最多 $n$ 個字元，所以整體大約是：

$$
O(n \times 2^n)
$$

2. **空間複雜度**：遞迴深度是 $n+1$ 層。因為 `a` 是用傳值的，每一層都會有自己的一份長度為 $n$ 的字串，再加上 `current`，所以總共大約是：

$$
O(n^2)
$$

3. 如果把 `a` 改成參考傳遞（`const string &a`），就不用每層都複製，空間可以降到 $O(n)$。
4. 這份程式不會去除重複，如果輸入有相同的字元，就會印出一樣的子集合，但總行數還是 $2^n$ 行。

## 結論

1. 這程式用每個字元選或不選的遞迴，印出所有子集合，每個測試的行數都剛好是 $2^n$。
2. 終止條件是 `index == a.length()`，到這時候 `current` 就是一個完整的子集合。
3. 空集合會最先出現，因為每一層都先走「不選」，最後印出來的就是空字串。
4. 時間複雜度是 $O(n \times 2^n)$，空間複雜度是 $O(n^2)$，改成參考傳遞的話可以降到 $O(n)$。
5. 子集合的數量是指數成長，字元多的話輸出量就會爆炸。
6. 如果輸入相同字元的話會印出重複的子集合。

## 申論及開發報告

### 想法是怎麼來的

一開始看到所有子集合，我先從最小的例子慢慢數：`{A}` 只有空集合和A兩個；加上 `B` 之後，原本的每個子集合都可以選擇「不加 B」或「加 B」，所以變 4 個；再加 `C` 就變 8 個。每多一個元素，數量就乘 2，也就是 $2^n$。

這個規律剛好可以直接寫成遞迴，每個字元都有兩條路，而且走完這一步之後，剩下的就是少一個字元的同樣問題，所以兩次遞迴呼叫就搞定了。

### 用 `AB` 看一次執行過程

以輸入 `AB` 為例，呼叫 `powerset("AB", 0, "")` 的過程是這樣：

```text
powerset(index=0, current="")
├─ 不選 A → powerset(index=1, current="")
│    ├─ 不選 B → powerset(index=2, current="")   輸出 ""
│    └─ 選 B   → powerset(index=2, current="B")  輸出 "B"
└─ 選 A   → powerset(index=1, current="A")
     ├─ 不選 B → powerset(index=2, current="A")  輸出 "A"
     └─ 選 B   → powerset(index=2, current="AB") 輸出 "AB"
```

從上往下依序印出：空字串、`B`、`A`、`AB`，剛好 4 個。整個遞迴就像一棵二元樹，深度等於字元數，最下面就是答案。

### 跟位元遮罩（Bitmask）的比較

子集合還有一種不用遞迴的寫法：讓整數從 $0$ 數到 $2^n-1$，把每個數字看成 $n$ 位元的二進位，某一位是 1 就代表選那個字元。例如 `ABC` 的 `101` 就是 `AC`。這種寫法只要兩層迴圈，比較快也不用擔心遞迴深度。不過遞迴版比較能看出選或不選的決策過程，而且之後如果要加條件（例如只要總和是某個值的子集合）也比較好改，所以這題我選擇用遞迴。

### 程式還可以改進的地方

1. 把 `string a` 改成 `const string &a`，這樣不用每層都複製一次原字串。
2. 如果不想要重複的子集合，可以先把字串排序，在不選某個字元之後，跳過後面一樣的字元。
3. 原本的程式裡，第一個 `powerset(...)` 後面多打了一個分號，也引入了沒用到的 `<algorithm>`，雖然不影響結果，但整理的時候可以順便清掉。

### 遞迴的優缺點

好處是程式很短，核心只有兩行遞迴，而且跟選或不選的想法一樣。缺點是子集合是 $2^n$ 個，字元一多就會爆炸，例如：

```text
2^5  = 32
2^10 = 1024
2^15 = 32768
2^20 = 1048576
```

所以字元超過 20 個左右，光是印出來就要花很久，這個方法只適合元素比較少的情況。

# 作業總結

這次作業的兩題都跟遞迴有關，但用法不太一樣。

## 題目一：Ackermann Function

這題的重點是照著定義寫，而且我另外找規律寫了一份非遞迴版來比較。透過這題我了解了終止條件怎麼設計、遞迴深度的問題，也知道有些遞迴問題只要先分析透，就能用更省的方式處理。

```text
m == 0
    ↓
n + 1

m > 0 且 n == 0
    ↓
A(m-1, 1)

m > 0 且 n > 0
    ↓
A(m-1, A(m, n-1))
```

## 題目二：Power Set

這題的重點是「每個元素選或不選」，每個字元分兩條路，最後的葉節點就是所有子集合，數量是 $2^n$。

```text
決定第 index 個字元
    ↓
        ┌─ 不選：current 不變
        │
        └─ 選：current + a[index]
    ↓
index 走到字串尾端
    ↓
印出 current
```

# 複雜度比較

| 題目 | 主要演算法 | 時間複雜度 | 空間複雜度 |
|------|------------|------------|------------|
| 題目一 Ackermann（遞迴） | 遞迴 | 呼叫次數隨 Ackermann 函數暴增 | $O(\text{recursion depth})$ |
| 題目一 Ackermann（非遞迴） | 公式 + 迴圈（`m ≤ 3`） | $O(1)$ 或 $O(n)$ | $O(1)$ |
| 題目二 Power Set | 遞迴（二元分支） | $O(n \times 2^n)$ | $O(n^2)$ |

結論：

- Ackermann遞迴：照著公式寫程式會很好懂，但自己呼叫自己太多層，小麻煩，數字一大就容易當掉。
- Ackermann非遞迴：先找規律再直接算會比較快，但只能處理 `m ≤ 3`。
- Power Set：每個字元都有要或不要兩種選擇，全部組合起來就是所有子集合。
